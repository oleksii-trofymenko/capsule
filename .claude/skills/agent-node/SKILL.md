# Agent node

1. **Contract.** Define the node's input and output as Pydantic models. A node reads only the state fields it needs and writes only its own.
2. **Single job.** One node, one responsibility (parse request, ask follow-ups, retrieve trends, search products, validate budget, write guide, check output).
3. **Model calls.** Through the LiteLLM gateway only, with `AsyncOpenAI` (base URL and the service's virtual key from settings, `max_retries=0`, explicit timeout) and a logical route name from gateway config (today `agent-parse`, `agent-guide`, `vision`, `embed`; a new route is a gateway-config change named in the card; ADR-010). Never a model name, provider or LangChain chat-model wrapper in code (ADR-009). Send the node name and the consultation trace id as request metadata. Two failure paths, kept apart: (a) gateway errors and timeouts are handled by the route's `fallbacks` in gateway config, which point only to another local route whose model is already resident in the VRAM budget, or to nothing; no cloud route while the budget is €0 (ADR-010); code never picks a fallback route; (b) output that fails the schema gets one repair retry on the same route. If either still fails, the node returns a typed failure, the graph answers "try again later" and keeps the checkpoint so the user can retry; it never crashes.
4. **Deterministic checks are code.** Budget sums, currency, product existence and links are checked in Python, not by a model.
5. **Limits.** Timeouts nest: gateway route timeout (time to first token for streams) × (1 + its fallbacks) < node timeout < graph total; values live in config and trace to the SLO in `docs/metrics.md`. Per-route timeouts are the only busy-GPU signal, because Ollama queues instead of rejecting (ADR-010). Loops (clarify, re-pick within budget) have a max count.
6. **State.** Checkpointed in Postgres (`langgraph-checkpoint-postgres`, separate `agent_checkpoint` schema created by an Alembic migration, never by `setup()` at runtime; ADR-009) so a conversation resumes after a follow-up question or a "try again later". Checkpoints are deleted when the consultation closes or expires, because state holds personal data. The migration is a `backend-engineer` card: pin `langgraph-checkpoint-postgres`, copy its DDL and its `checkpoint_migrations` rows (so a stray `setup()` does nothing), connect with `search_path=agent_checkpoint`; a version bump ports new DDL in a new migration. `thread_id` is the consultation id, never personal data. A SAQ job calls `delete_thread` on close, on TTL expiry (value from the E1 guest-data retention ADR) and on "Delete my data".
7. **Tracing.** One Langfuse span per model call with node, route, the resolved model returned by the gateway, tokens and latency; no raw photos, no personal data. One source only: the E3 gateway card picks either the gateway's Langfuse callback (message content off, images redacted, ADR-010) or the node, never both.
8. **Tests.** Unit test on recorded fixtures (no live model) for the happy path, invalid model output and timeout.
9. **Eval.** If the node changes answers, run the `eval-run` skill and put the delta in the PR.
